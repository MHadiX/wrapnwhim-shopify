# QA evidence and launch checklist

## What was tested locally

The test harness renders this repository's Liquid sections/snippets and layouts using LiquidJS and a controlled fixture catalog. Shopify-specific tags/filters and Ajax endpoints have **test doubles**. The delivered theme itself uses Shopify APIs; no mocked catalog, inventory, orders or checkout behavior ships in its assets.

Commands:

```sh
npm run check
npm test
npm run test:browser
npm run test:a11y
npm run package
```

- Shopify Theme Check: no offenses in the completed theme.
- Commerce regression tests: 7 passing tests covering exact variant resolution, genuine component totals, grouping/properties, missing selections, invalid quantities, quantity rules, sold-out state, bounded messages, upload validation and currency formatting.
- Chromium browser suite: 24 passing flow checks. The responsive check covers nine rendered templates at 320, 390, 768, 1440 and 1920px and decodes images to detect missing assets.
- Automated axe WCAG 2 A/AA and WCAG 2.1 A/AA checks: no violations on the audited homepage, product, collection, builder, contact, wishlist, search and open predictive-search dialog using default colors and fixture content. Automated results do not establish full accessibility compliance; merchant content/color changes and assistive-technology testing still require review.
- Repository design screenshots are available in `docs/previews/` and are explicitly labeled as local fixture previews in README; they are excluded from the installable theme ZIP.
- Browser screenshots: `test-results/home-desktop.png` and `home-mobile.png`, generated by the current test run. Results JSON files record the fixture limitation and individual outcomes. These are ignored development outputs.
- Shopify CLI generates the installable theme archive. The archive includes native theme directories and excludes tests, scripts, npm modules and documentation.

Browser flows exercised: desktop mega menu, mobile dialog focus containment/Escape, slide controls/dots/swipe and reduced motion, product carousel and quick view, variant pricing/unavailable states, required personalization/counting/escaped preview, Ajax add with an inventory error, cart quantity changes/removal/property retention/refresh, upload validation/local preview, fullscreen image gallery, predictive-search keyboard navigation, browser wishlist persistence/removal, builder step validation/reload/actual totals/cart payload grouping, note-saving and native checkout handoff, sorting query submission, and required contact/newsletter inputs. Additional revision checks cover category expansion, all eleven occasion destinations and scrolling, consistent portrait product media, aligned visible purchase actions, responsive filter panels without desktop grid movement, card quick-add quantity rules/server errors, search product cards, editor font/color/image settings overriding stylesheet defaults, the compact phone/tablet header and card controls, and mobile purchase-bar validation, variant price/stock, cart properties and desktop hiding. Browser JavaScript errors are also checked.

The responsive renderer is not Shopify's actual Liquid engine. Theme Check supplies Shopify-specific static validation; an actual development store is required for runtime compatibility verification. Filtering/search ranking/inventory enforcement/consent/email delivery are Shopify services and are not established by mock responses.

## Uploaded compatibility reference

The uploaded Horizon 4.3.0 theme was inspected only as a compatibility reference. Its native directories, JSON section templates, product resources, forms and filtering architecture were compared with this theme. Its design, merchant settings, product identifiers and assets were not imported. Horizon’s Theme Check run reported 8 offenses (2 errors and 6 warnings) in the supplied export; those findings do not belong to the delivered WrapnWhim source. WrapnWhim’s own Theme Check run inspected 94 files with zero offenses. A reference export cannot replace runtime testing on an actual Shopify development store.

## Required real Shopify development-store checks

Use an unpublished theme with actual products and test payment mode. Retain these as pending until executed:

| Area | Live validation |
| --- | --- |
| Editor | Load every JSON template, add/reorder sections, edit each setting and preview mobile/desktop. Confirm fonts, logo, collections, image crops, menus, app blocks and locale routes. |
| Product | Test every actual option combination, image/SKU/price updates, sold-out variants, quantity restrictions and add errors. Test video controls; review any external video consent requirements. |
| Personalization | Submit every configured required/optional field; check cart, refresh, quantity update, checkout and actual Admin order line properties. Verify labels are unique. |
| Photo | Submit a real allowed image using native multipart form; test oversized/invalid/required errors, stored file link and retention in Admin after checkout. Confirm Shopify's actual supported size limits. |
| Paid options | Compare actual wrapping/card variant prices to checkout amounts; do not use a property to charge a fee. |
| Gift box | Configure role products and min/max; test each size/item/card/wrap, price changes, stock races, out-of-stock errors and final order grouping. Merchant must verify packing and fulfillment workflow. Checkout-level capacity or inseparable bundles require the documented app. |
| Cart | Test discount allocations, add errors, quantity errors, multiple same-product customizations, remove all/empty state, locale URLs, note saving and checkout. Confirm properties never disappear. |
| Search/collections | Enable filters, test real price/availability/type filters and removal, counts, sort order, pagination, keyboard suggestions, empty results and API/network errors. |
| Forms | Submit contact and newsletter; verify Shopify receipt, email/subscriber record and consent state; review spam/CAPTCHA behavior and real success/error messages. |
| Accounts | Test the merchant's selected new/classic flow. Classic: sign-up/login/recovery/addresses/orders/logout. New accounts: Shopify-hosted navigation/return routes. |
| Pakistan checkout | Confirm PKR, shipping zones/cities, delivery rates, taxes, COD and supported payment gateways with a real test order. No provider availability is assumed. |
| Tracking | Confirm order-confirmation links and actual fulfillment tracking URLs; no independent carrier lookup is supplied. |
| Accessibility | Real keyboard-only flow, VoiceOver/TalkBack/NVDA, zoom to 200–400%, touch devices, selected merchant colors, captions/transcripts for merchant videos and descriptive alt text. |
| Performance/SEO | Run Lighthouse on the actual served theme with merchant imagery/apps, check canonical/social metadata, product structured data and Shopify consent tooling. No Lighthouse/Core Web Vitals score is claimed from a local fixture. |
| Policies/content | Replace demo imagery, configure real links, support details, genuine reviews, brand story and merchant-approved policies. Verify all navigation and CTA destinations. |

## Known scope limits

No Shopify store domain/authentication was provided, so no development-store installation, payment, file-retention, actual order, email-delivery or live publication test was performed. No paid apps or external backends were provisioned. Guest wishlists are local to the browser. Gift boxes are separate Shopify products grouped for merchant assembly; an enforced native bundle requires the integration described in `INTEGRATIONS.md`.
